The Gaming Room: Draw It or Lose It
Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
The Gaming Room wanted to expand its existing Android game, Draw It or Lose It, into a web-based application accessible on multiple operating systems and devices. The application needed to support multiple games, teams, and players; enforce unique game and team names; and maintain consistent game data. The design also needed to address performance, storage, network communication, and security.
What did you do particularly well in developing this documentation?
I organized the requirements and explained how the application's components work together. I described the relationships among the Entity, Game, Team, Player, and GameService classes, and how inheritance and the Singleton design pattern support reusable code and centralized game management. I also connected the operating platform, memory, storage, networking, and security recommendations to the client's goals.
What about the process of working through a design document did you find helpful when developing the code?
Creating the design document helped me clarify the requirements before coding. The UML diagram made the class relationships and responsibilities easier to understand, which helped me identify the attributes, methods, and design patterns the application needed. Planning these details first gave the code a clearer structure.
If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
I would expand the distributed systems and network design. I would add an architecture diagram showing the connections among browser clients, application servers, and the database. I would also document how the application should respond to disconnections, server outages, concurrent requests, and increasing traffic so developers have more specific implementation guidance.
How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?
I translated the client's goals into requirements for cross-platform access, multiple teams and players, unique names and identifiers, and consistent game sessions. I recommended a Linux-based server with web clients so users on different devices could share the same application. Considering user needs is essential because technical decisions should support the experience the client wants and reduce costly changes later.
How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
I started by identifying the business and technical requirements, then modeled the domain objects and their relationships. I used object-oriented principles, UML, design patterns, and comparisons of operating systems to evaluate possible solutions. For future projects, I would follow the same requirements-first approach while adding more detailed architecture diagrams, early security reviews, scalability planning, and testing of failure scenarios.
